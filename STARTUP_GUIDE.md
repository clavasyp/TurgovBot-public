# TurgovBot — Полное руководство по запуску

---

## Что вообще происходит?

Раньше бот запускался просто: `python main.py` прямо на сервере. Все зависимости стояли глобально, база данных PostgreSQL крутилась там же.

Теперь мы переходим на **Docker** — это система, которая упаковывает приложение и все его зависимости в изолированные «контейнеры». Представь это как отдельные коробки: в одной — база данных, в другой — бот, в третьей — API. Они общаются между собой, но каждая работает независимо.

**Зачем это нужно:**
- Не нужно устанавливать Python, PostgreSQL и прочее на сервер вручную — всё внутри контейнеров
- Обновление = одна команда, а не «стопни бот, обнови код, перезапусти»
- Если что-то сломалось — контейнер автоматически перезапустится
- Через GitHub Actions код пушится → автоматически собирается → деплоится на сервер

## 1. Что нужно установить перед началом

На сервере (или на локальной машине) должно быть установлено только **два** инструмента: Docker и Git.

### Установка Docker (Linux / Ubuntu / Debian)

Откройте терминал (подключитесь к серверу через SSH) и выполните:

```bash
# Эта команда скачает и установит Docker автоматически
curl -fsSL https://get.docker.com | sh
```

После установки нужно дать вашему пользователю право запускать Docker без `sudo`:

```bash
# Замените $USER на имя вашего пользователя, если вы под root
sudo usermod -aG docker $USER
```

**Важно:** после этой команды нужно **перелогиниться** (выйти из SSH и зайти заново), чтобы права применились.

Проверьте, что всё установилось:

```bash
docker --version
# Должно показать что-то вроде: Docker version 24.0.x

docker compose version
# Должно показать что-то вроде: Docker Compose version v2.20.x
```

Если `docker compose version` не работает — значит Docker слишком старый. Обновите по инструкции выше.

### Установка Git

На большинстве серверов Git уже есть. Проверьте:

```bash
git --version
```

Если нет:

```bash
sudo apt update && sudo apt install -y git
```

## 2. Структура проекта — что где лежит

После клонирования репозитория вот что важно знать:

```
TurgovBot/
│
├── .env.example          ← Шаблон настроек. Копируешь в .env и заполняешь
├── .env                  ← Твои РЕАЛЬНЫЕ настройки (пароли, токены). В Git НЕ попадает!
│
├── credentials/          ← Папка для JSON-ключей Google (создаёшь сам)
│   ├── turgovbot-e049415b13c9.json
│   ├── credentials.json
│   ├── majestic-rp-bot-*.json
│   ├── client_secret_*.json
│   └── token_gdocs.json
│
├── docker-compose.yml    ← Главный файл — описывает что и как запускать
├── Dockerfile            ← «Рецепт» для сборки контейнера бота и API
├── Dockerfile.parser-worker ← «Рецепт» для парсера (с браузером Chromium)
│
├── scripts/
│   ├── backup_db.sh      ← Скрипт бэкапа базы данных
│   ├── restore_db.sh     ← Скрипт восстановления из бэкапа
│   └── migrate_to_docker.sh ← Скрипт миграции существующей БД в Docker
│
├── data/                 ← JSON-файлы с данными (пользователи, настройки)
├── logs/                 ← Логи бота
└── backups/              ← Бэкапы базы данных (создаётся автоматически)
```

### Какие сервисы (контейнеры) запускаются

Docker стартует **4 контейнера**, которые работают вместе:

| Контейнер | Что делает | Порт |
|---|---|---|
| **db** | PostgreSQL — база данных. Хранит всех пользователей, историю, настройки | 5432 (только локально) |
| **bot** | Telegram-бот — `main.py`. Обрабатывает сообщения пользователей | нет внешнего порта |
| **api** | REST API — FastAPI сервер. Веб-интерфейс для управления | 8000 |
| **parser-worker** | Парсер форумов — запускает браузер Chromium внутри контейнера | 8765 (только локально) |

**Порядок запуска** (Docker делает это автоматически):
1. Сначала стартует **db** (база данных)
2. Docker ждёт, пока база скажет «я готова принимать запросы»
3. Только после этого стартуют **bot**, **api** и **parser-worker** параллельно

## 3. Сценарий А: Миграция (бот уже работает, база не пустая)

> Используй этот сценарий, если бот уже запущен на сервере и в PostgreSQL есть данные (пользователи, настройки, история), которые нельзя потерять.

### Шаг 1: Скачай новый код

Подключись к серверу по SSH и перейди в папку с ботом:

```bash
cd /путь/к/TurgovBot

# Скачай ветку с Docker-инфраструктурой
git fetch origin
git checkout docker-infrastructure
```

### Шаг 2: Создай файл `.env` с настройками

Файл `.env` — это список всех паролей, токенов и настроек. Бот читает их оттуда при запуске.

```bash
# Копируем шаблон
cp .env.example .env
```

Теперь открой файл `.env` в текстовом редакторе:

```bash
nano .env
```

> **Как пользоваться nano:** стрелками перемещаешься, печатаешь текст. Для сохранения: `Ctrl+O`, затем `Enter`. Для выхода: `Ctrl+X`.

Заполни каждую строку **реальными значениями**. Вот что значит каждая переменная:

```ini
# === БАЗА ДАННЫХ ===
# Это логин и пароль от PostgreSQL. Если не менял — оставь как было.
DB_USER=bot_db_user          # Имя пользователя БД (то же, что было раньше)
DB_PASS=твой_пароль_от_бд    # Пароль от БД (то же, что было раньше)
DB_HOST=db                   # НЕ МЕНЯТЬ! Это имя контейнера внутри Docker
DB_PORT=5432                 # НЕ МЕНЯТЬ! Стандартный порт PostgreSQL
DB_NAME=bot_database         # Имя базы данных (то же, что было раньше)

# === TELEGRAM ===
# Токен от @BotFather
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz

# === GOOGLE CLOUD ===
# ID твоего проекта в Google Cloud Console
GCP_PROJECT_ID=turgovbotv3
GCP_REGION=global
GCS_BUCKET_NAME=turgovbot

# Имена JSON-файлов с ключами (только имена, не пути!)
# Сами файлы будут лежать в папке credentials/
VERTEX_CREDENTIALS_FILE=turgovbot-e049415b13c9.json
GOOGLE_CREDENTIALS_FILE=credentials.json
SPEECH_TO_TEXT_CREDENTIALS_FILE=majestic-rp-bot-0ccbaf125d81.json

# === GOOGLE SHEETS ===
# ID таблицы из URL: https://docs.google.com/spreadsheets/d/ВОТ_ЭТОТ_ID/edit
SPREADSHEET_ID=1HxTfgBWm57l2oKyfGNcLeUb9LqKC2_cZZ7ZKk22DZx8

# === ПРОКСИ ===
# Формат: хост:порт:логин:пароль
# Если прокси нет — оставь пустым
IMGUR_SOCKS5_PROXY=
FORUM_HTTP_PROXY=

# === ПАРСЕР ===
# URL парсера внутри Docker-сети. НЕ МЕНЯТЬ!
PARSER_WORKER_URL=http://parser-worker:8765
# Секретный ключ для связи бота с парсером (любая случайная строка)
PARSER_SECRET_KEY=придумай_длинную_случайную_строку

# === API СЕРВЕР ===
API_SERVER_HOST=0.0.0.0      # НЕ МЕНЯТЬ!
API_SERVER_PORT=8000          # Порт API. Можно поменять если 8000 занят

# === АДМИНИСТРАТОР ===
# Твой Telegram User ID (число). Узнать: отправь /start боту @userinfobot
SUPER_ADMIN_ID=123456789
```

Сохрани файл (`Ctrl+O`, `Enter`, `Ctrl+X`).

### Шаг 3: Подготовь Google-ключи (JSON-файлы)

Docker-контейнер не видит файлы, которые лежат просто в папке проекта. Нужно собрать все JSON-ключи в специальную папку `credentials/`, которая «подключается» к контейнеру.

```bash
# Создаём папку
mkdir -p credentials
```

Теперь скопируй туда **все** JSON-файлы с ключами. Они у тебя уже лежат в корне проекта:

```bash
# Vertex AI ключ
cp turgovbot-e049415b13c9.json credentials/

# Google Sheets ключ
cp credentials.json credentials/

# Speech-to-Text ключ
cp majestic-rp-bot-*.json credentials/

# OAuth для Google Docs (экспорт документов)
cp client_secret_*.json credentials/
cp token_gdocs.json credentials/
```

Проверь что файлы на месте:

```bash
ls -la credentials/
```

Должен увидеть 4-5 файлов с расширением `.json`.

### Шаг 4: Останови текущего бота

Прежде чем запускать Docker-версию, нужно остановить текущего бота, иначе два бота будут конфликтовать.

```bash
# Если бот запущен через systemd:
sudo systemctl stop turgovbot

# Если бот запущен через screen:
screen -r turgovbot   # подключаемся к сессии
# Нажми Ctrl+C чтобы остановить бота
# Нажми Ctrl+A, затем D чтобы выйти из screen

# Если бот запущен просто в фоне:
# Найди процесс и убей его:
ps aux | grep main.py
kill <номер_процесса>
```

**НЕ ОСТАНАВЛИВАЙ PostgreSQL пока!** Он нужен для Шага 5.

### Шаг 5: Перенеси базу данных в Docker

Этот скрипт сделает всё автоматически: создаст бэкап текущей БД, запустит PostgreSQL в Docker, перенесёт данные.

```bash
# Даём скрипту право на запуск
chmod +x scripts/migrate_to_docker.sh

# Запускаем миграцию
./scripts/migrate_to_docker.sh
```

**Что происходит внутри скрипта (не нужно делать вручную):**
1. Скрипт подключается к твоей текущей БД и создаёт полный бэкап → сохраняет в `backups/`
2. Запускает новый контейнер PostgreSQL в Docker
3. Загружает бэкап в этот новый контейнер
4. Проверяет что данные на месте (покажет количество таблиц и пользователей)

В конце ты увидишь:
```
==========================================
  ✅ МИГРАЦИЯ ЗАВЕРШЕНА УСПЕШНО
==========================================
   Таблиц: XX
   Пользователей: XX
```

Если числа совпадают с тем, что было — всё ок.

### Шаг 6: Примени миграции Alembic

Alembic — это инструмент, который обновляет структуру базы данных (добавляет новые таблицы/колонки если нужно). Запускаем его одной командой:

```bash
docker compose run --rm migrate
```

> `--rm` означает «удали контейнер после выполнения». Это одноразовая задача, контейнер не нужен постоянно.

### Шаг 7: Запусти все сервисы

```bash
docker compose up -d
```

> `-d` означает «в фоне» (detached). Без этого флага логи будут печататься в терминал и при закрытии терминала всё остановится.

### Шаг 8: Проверь что всё работает

```bash
# Покажет статус всех контейнеров
docker compose ps
```

Все 4 контейнера должны быть в статусе `running` или `Up`:

```
NAME                    STATUS
turgovbot-db-1          Up (healthy)     ← база данных готова
turgovbot-bot-1         Up               ← бот работает
turgovbot-api-1         Up (healthy)     ← API сервер работает
turgovbot-parser-worker-1  Up (healthy)  ← парсер работает
```

Если хочешь посмотреть логи бота в реальном времени:

```bash
docker compose logs -f bot
```

> Чтобы выйти из просмотра логов — нажми `Ctrl+C`. Это **не** остановит бота, просто закроет просмотр логов.

Проверь что API отвечает:

```bash
curl http://localhost:8000/health
```

Должен вернуться JSON с `"status": "ok"` или подобным.

Напиши боту в Telegram — он должен отвечать.

### Шаг 9: Отключи старый PostgreSQL (после проверки)

Когда убедился, что Docker-версия работает нормально (бот отвечает, данные на месте), можно отключить локальный PostgreSQL чтобы он не занимал ресурсы:

```bash
sudo systemctl stop postgresql
sudo systemctl disable postgresql
```

> `disable` означает «не запускать при перезагрузке сервера». Если захочешь включить обратно: `sudo systemctl enable postgresql && sudo systemctl start postgresql`.

## 5. Повседневное использование — шпаргалка

### Запуск и остановка

```bash
# Перейди в папку с проектом (если ещё не там)
cd /opt/TurgovBot

# Запустить ВСЕ сервисы
docker compose up -d

# Остановить ВСЕ сервисы
# Данные НЕ потеряются — база данных хранится в Docker volume
docker compose down

# Перезапустить только бота (например после изменения .env)
docker compose restart bot

# Перезапустить только API
docker compose restart api

# Перезапустить парсер
docker compose restart parser-worker
```

### Просмотр логов

```bash
# Логи ВСЕХ сервисов сразу
docker compose logs -f

# Логи только бота
docker compose logs -f bot

# Логи только API
docker compose logs -f api

# Логи только парсера
docker compose logs -f parser-worker

# Последние 200 строк логов бота (без слежения в реальном времени)
docker compose logs --tail=200 bot
```

> Во всех случаях `Ctrl+C` — выйти из просмотра логов. Сам сервис НЕ остановится.

### Статус

```bash
# Показать что запущено
docker compose ps

# Показать сколько памяти/CPU занимает каждый контейнер
docker stats --no-stream
```

### Обновление кода

Когда ты (или CI/CD) обновил код:

```bash
cd /opt/TurgovBot

# Скачать новый код
git pull

# Пересобрать образы (Docker возьмёт новый код)
docker compose build

# Применить миграции (если были изменения в структуре БД)
docker compose run --rm migrate

# Перезапустить с новыми образами
docker compose up -d
```

### Изменение настроек `.env`

Если поменял что-то в `.env`:

```bash
# Контейнеры нужно пересоздать, чтобы они подхватили новые переменные
docker compose down
docker compose up -d
```

> Простой `restart` НЕ подхватит изменения в `.env`. Нужен именно `down` + `up`.

## 6. Настройка автодеплоя через GitHub Actions

### Что это и зачем

Автодеплой работает так:
1. Ты пушишь код в ветку `master` на GitHub
2. GitHub автоматически собирает Docker-образы
3. GitHub по SSH подключается к серверу и обновляет контейнеры
4. Перед обновлением автоматически делается бэкап БД

То есть после настройки достаточно просто сделать `git push` — и новая версия окажется на сервере.

### Как настроить (пошагово)

#### 1. Зайди в настройки репозитория на GitHub

Открой https://github.com/clavasyp/TurgovBot → вкладка **Settings** (вверху) → в левом меню **Secrets and variables** → **Actions**.

#### 2. Добавь секреты

Нажми кнопку **"New repository secret"** и добавь по одному каждый секрет:

**`DEPLOY_HOST`** — IP-адрес твоего сервера.
Пример: `203.0.113.10`

**`DEPLOY_USER`** — имя пользователя SSH на сервере.
Пример: `root` или `deploy` или `ubuntu`

**`DEPLOY_SSH_KEY`** — приватный SSH-ключ для подключения к серверу.
Как получить:
```bash
# НА СЕРВЕРЕ:
cat ~/.ssh/id_ed25519
# Если файла нет, создай ключ:
ssh-keygen -t ed25519 -C "github-deploy"
cat ~/.ssh/id_ed25519
```
Скопируй ВСЁ содержимое (включая `-----BEGIN` и `-----END`) и вставь как значение секрета.

Также убедись, что публичный ключ добавлен в `~/.ssh/authorized_keys` на сервере:
```bash
cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
```

**`DEPLOY_PATH`** — полный путь к папке проекта на сервере.
Пример: `/opt/TurgovBot`

#### 3. Протестируй

Зайди на GitHub → вкладка **Actions** → выбери **CI/CD Deploy** → нажми **Run workflow** → **Run workflow**.

Подожди пару минут. Если всё зелёное ✅ — автодеплой работает.

#### 4. Когда срабатывает автоматически

Автодеплой срабатывает при каждом пуше в ветку `master`:
```bash
git checkout master
git merge docker-infrastructure
git push
```

## 7. Бэкапы: как не потерять данные

### Ручной бэкап

```bash
cd /opt/TurgovBot

# Даём скрипту право на запуск (нужно сделать только один раз)
chmod +x scripts/backup_db.sh

# Создаём бэкап
./scripts/backup_db.sh
```

Файл бэкапа сохранится в `backups/turgovbot_YYYYMMDD_HHMMSS.sql.gz` (дата и время в имени).

Скрипт автоматически удаляет бэкапы старше 30 дней.

### Восстановление из бэкапа

> ⚠️ Восстановление **полностью перезапишет** текущую базу данных! Делай это только если уверен.

```bash
# Даём скрипту право на запуск (нужно сделать только один раз)
chmod +x scripts/restore_db.sh

# Посмотри какие бэкапы есть
ls -la backups/

# Восстанови из конкретного бэкапа
./scripts/restore_db.sh backups/turgovbot_20260412_120000.sql.gz
```

Скрипт спросит подтверждение перед восстановлением.

### Автоматические бэкапы (каждый день)

Чтобы бэкапы создавались автоматически каждую ночь:

```bash
# Открой редактор cron-задач
crontab -e
```

> Если спросит какой редактор — выбери `1` (nano).

Добавь в конец файла эту строку:

```
0 3 * * * /opt/TurgovBot/scripts/backup_db.sh >> /opt/TurgovBot/logs/backup.log 2>&1
```

Это означает: каждый день в 3:00 ночи запускать бэкап. Логи бэкапа пишутся в `logs/backup.log`.

Сохрани (`Ctrl+O`, `Enter`, `Ctrl+X`).

### Где хранить бэкапы надёжно

Бэкапы на том же сервере — это лучше чем ничего, но если сервер сломается — потеряешь и бэкапы. Рекомендую периодически копировать бэкапы к себе:

```bash
# С ЛОКАЛЬНОЙ МАШИНЫ (не с сервера):
scp user@сервер:/opt/TurgovBot/backups/*.sql.gz ~/мои_бэкапы/
```

## 8. Проблемы и их решения

### Бот не отвечает в Telegram

**Шаг 1:** Проверь что контейнер бота запущен:
```bash
docker compose ps bot
```
Должен быть статус `Up`. Если `Exited` или `Restarting` — читай логи (Шаг 2).

**Шаг 2:** Посмотри логи бота:
```bash
docker compose logs --tail=100 bot
```

**Частые ошибки:**
- `Invalid token` → неправильный `TELEGRAM_BOT_TOKEN` в `.env`
- `Connection refused` к базе → контейнер `db` не запущен или не готов
- `ModuleNotFoundError` → образ не собран. Выполни `docker compose build bot`

### API не отвечает (порт 8000)

```bash
# Проверь статус
docker compose ps api

# Посмотри логи
docker compose logs --tail=100 api

# Попробуй запросить вручную
curl http://localhost:8000/health
```

Если curl выдаёт `Connection refused`:
- API контейнер не запущен → `docker compose up -d api`
- Порт 8000 занят другим приложением → поменяй `API_SERVER_PORT` в `.env` и `docker compose down && docker compose up -d`

### База данных не стартует

```bash
docker compose logs db
```

**Частые причины:**
- Порт 5432 уже занят локальным PostgreSQL:
  ```bash
  # Проверь кто занимает порт
  sudo lsof -i :5432

  # Если это локальный PostgreSQL — останови его
  sudo systemctl stop postgresql
  ```
- Не хватает места на диске:
  ```bash
  df -h
  ```

### Парсер не работает

```bash
docker compose logs --tail=100 parser-worker
```

Парсер использует браузер Chromium внутри контейнера. Ему нужно минимум **512 MB RAM**.

Проверь доступную память:
```bash
free -h
```

### Контейнер постоянно перезапускается

Если `docker compose ps` показывает `Restarting`:

```bash
# Посмотри последние логи перед падением
docker compose logs --tail=50 имя_контейнера
```

Замени `имя_контейнера` на `bot`, `api`, `db` или `parser-worker`.

### Нужно зайти внутрь контейнера (для отладки)

```bash
# Открыть bash внутри контейнера бота
docker compose exec bot bash

# Внутри можешь запускать Python, смотреть файлы и т.д.
python -c "from config import TELEGRAM_BOT_TOKEN; print('Token:', TELEGRAM_BOT_TOKEN[:10] + '...')"

# Выйти из контейнера
exit
```

### Нужно подключиться к базе данных вручную

```bash
docker compose exec db psql -U bot_db_user -d bot_database
```

Откроется консоль PostgreSQL. Примеры команд:

```sql
-- Количество пользователей
SELECT COUNT(*) FROM users;

-- Список таблиц
\dt

-- Выйти
\q
```

### После docker compose down потеряются ли данные?

**НЕТ.** Данные базы данных хранятся в Docker volume (`turgovbot_pgdata`). Команда `docker compose down` останавливает контейнеры, но volume остаётся.

Данные потеряются **только** если выполнить:
```bash
docker compose down -v   # ← -v удаляет volumes! НЕ ДЕЛАЙ ЭТО без бэкапа!
```

### Как полностью пересоздать всё с нуля

> ⚠️ Это удалит ВСЕ данные! Сделай бэкап первым!

```bash
./scripts/backup_db.sh
docker compose down -v
docker compose up -d db
sleep 10
docker compose run --rm migrate
docker compose up -d
```
